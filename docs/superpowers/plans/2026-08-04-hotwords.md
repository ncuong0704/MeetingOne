# Hotwords Implementation Plan (sherpa-onnx path)

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking. Execute tasks in order; each task ends with a commit. Do not skip "run and verify" steps.

**Goal:** Let users enter a list of proper nouns / specialized terms in Settings that bias the ASR toward recognizing them correctly — for the existing single-model (`asr_engine`, sherpa-onnx) path only. Editing the list takes effect on the very next transcription, no model reload required.

**Architecture:** Sherpa-onnx's Rust binding already has hotword support at the config layer (`OfflineRecognizerConfig.hotwords_file`/`hotwords_score`) and, more usefully, `OfflineRecognizer::create_stream_with_hotwords(&self, hotwords: &str)` — hotword text passed **per transcribe call**, not baked into the loaded model. Sherpa-onnx does its own phrase→BPE-piece encoding internally; Meetily only needs to (1) generate a `bpe.vocab` (piece+score text file) from each model's binary `bpe.model` once, via the new pure-Rust `sentencepiece-model` crate, and (2) set `modeling_unit`/`bpe_vocab` at model-load time, and (3) pass the user's (comment/blank-line-stripped) hotword text into `create_stream_with_hotwords` on every transcribe call.

**Tech Stack:** Rust (`sentencepiece-model` crate — new, pure Rust, no `protoc` needed), sqlx/SQLite migration, TypeScript/React.

**Reference spec:** `docs/superpowers/specs/2026-08-04-hotwords-design.md`

**Verified before writing this plan:** the `sentencepiece-model` crate's exact API (`SentencePieceModel::from_file`, `.pieces() -> &[SentencePiece]`, `SentencePiece { piece: Option<String>, score: Option<f32>, .. }`) was checked against its actual `.proto` source and `lib.rs`, not assumed. `create_stream_with_hotwords`'s signature was checked against the real `sherpa-onnx` 1.13.0 crate source. Every Rust snippet below is a diff against the actual current content of `asr_engine/engine.rs`, `asr_engine/commands.rs`, `database/models.rs`, `database/repositories/setting.rs`, `api/api.rs`, and `AsrModelManager.tsx` — all re-read fresh after confirming Phase C (ROVER wiring) is already implemented in the working tree, since those files evolved during that phase.

```rust
use anyhow::{anyhow, Result};
use sentencepiece_model::SentencePieceModel;
use std::path::{Path, PathBuf};

/// Strips comment lines (`#...`) and blank lines from raw hotword text. Sherpa-onnx
/// natively understands the `PHRASE :score` syntax on each remaining line — Meetily does
/// not parse the score itself, only removes what sherpa-onnx wouldn't expect to see.
pub fn filter_hotwords_text(raw: &str) -> String {
    raw.lines()
        .map(|l| l.trim())
        .filter(|l| !l.is_empty() && !l.starts_with('#'))
        .collect::<Vec<_>>()
        .join("\n")
}

/// Ensures a `bpe.vocab` (piece\tscore per line) file exists next to `bpe_model_path`,
/// generating it from the binary SentencePiece model if missing (cached — regenerated
/// only if the `.vocab` file doesn't already exist). Returns `None`, not an error, on
/// failure: hotwords are an optional enhancement, and a bad/unreadable `bpe.model` must
/// not block loading the ASR model itself.
pub fn ensure_bpe_vocab(bpe_model_path: &Path) -> Option<PathBuf> {
    let vocab_path = bpe_model_path.with_extension("vocab");
    if vocab_path.exists() {
        return Some(vocab_path);
    }
    match generate_bpe_vocab(bpe_model_path, &vocab_path) {
        Ok(()) => Some(vocab_path),
        Err(e) => {
            log::warn!("Failed to generate bpe.vocab from {:?}: {}", bpe_model_path, e);
            None
        }
    }
}

fn generate_bpe_vocab(bpe_model_path: &Path, vocab_path: &Path) -> Result<()> {
    let model = SentencePieceModel::from_file(bpe_model_path)
        .map_err(|e| anyhow!("Failed to parse {:?}: {}", bpe_model_path, e))?;

    let mut out = String::new();
    for piece in model.pieces() {
        let text = piece.piece.as_deref().unwrap_or("");
        let score = piece.score.unwrap_or(0.0);
        out.push_str(text);
        out.push('\t');
        out.push_str(&score.to_string());
        out.push('\n');
    }

    std::fs::write(vocab_path, out).map_err(|e| anyhow!("Failed to write {:?}: {}", vocab_path, e))
}
```
